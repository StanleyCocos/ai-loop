# ai-loop 项目模型

## 目标

`ai-loop` 是一个一键完成项目需求的 AI 自动化系统，目标覆盖需求分析、反馈、任务编排、编码、测试、验收等全流程。

项目的核心诉求是把原本需要反复人工推进的流程固定下来，让任务从输入开始，自动流转到实现、验证和交付，而不是每次重新搭建上下文。

## 项目分层

- `core/`：Python 核心层，负责 AI agent 调度、任务编排和自动化控制逻辑。
- `dashboard/`：前台交互层，负责接收用户输入、展示运行日志和结果。
- `app/`：目标应用层，所有需求最终都围绕它进行编码、测试和验收。
- `docs/`：需求文档、背景说明和项目约定。
- `runs/`：每次运行的临时输入、过程产物和日志。
- `artifacts/`：构建产物、导出结果和最终交付物。

## 固定流程

项目当前固定为 6 个阶段：

1. 需求分析
2. 影响面分析
3. 产品审核
4. 测试策略
5. 编码
6. 验收

## 固定角色池

每个阶段都不是单一 agent，而是由多个不同身份的 agent 并行复盘，再由 `core` 汇总结论。

### 需求分析阶段

- 产品
- 高级工程师
- 架构师

### 影响面分析阶段

- 工程
- 架构
- 相关模块负责人

### 产品审核阶段

- 产品
- 设计
- 业务

### 测试策略阶段

- QA
- 工程
- 自动化测试

### 编码阶段

- 主实现
- 代码审查
- 关联模块校验

### 验收阶段

- 集成测试
- UI 验证
- 结果裁决

## 核心原则

- 需求先分析，再定稿。
- 每个阶段都要有多个视角复盘，避免单一角色判断片面。
- 实施前必须先定测试策略。
- 验收以集成测试为主，UI 场景还需要截图、像素对比等证据。
- `core` 负责创建、调度、汇总和裁决。

## 当前共识

目前已经确定的是：

- 6 个阶段固定不变；
- 每个阶段都固定一组角色池；
- 同一阶段内多个不同角色并行复盘；
- `core` 负责统一编排整个任务流。

## 待补充

后续还需要继续细化：

- 每个阶段的输入；
- 每个阶段的输出；
- 每个阶段的通过条件；
- 每个阶段的回退条件。
